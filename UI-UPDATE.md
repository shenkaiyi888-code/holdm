# Responsive table update

Run the existing server with `npm start`, or `npm run dev -- --host 0.0.0.0 --port 4173 --strictPort`.

The current art pass uses the older shared site's navy/emerald palette (`#0e1320` / `#1a2340` room, `#21865f` / `#146446` / `#0a3a29` felt). The engraved navy/ivory card back, smooth emerald felt and warm matte leather rail are individual ImageGen assets. The former material atlas remains in the library; the live interface loads the new textures directly. Animated room lighting, neutral-white card faces and the Apple-native UI font remain active. The final comparisons and visual checks are recorded in `design-qa.md` and `artifacts/art-polish-*.webp`.

This update keeps the poker engine, hand evaluation, betting rules, computer opponents, room APIs and SSE transport in `index.html` / `server.js`. It changes presentation through `ui-v2.css` and `ui-v2.js`. Existing deal, flip and chip flight animations are reused. Check uses two soft taps; opening bets and raises use distinct short chip sounds, routed through the existing mute preference.

Computer-player decisions now use the position/range policy in `poker-ai.js`, through the existing engine action path. It receives only the acting player's cards and a public-table snapshot. The strategy, integration and validation are described in `AI-UPDATE.md`; the portable preview embeds this module too.

`play.html` and `orientation-shell.js` keep one live game iframe. The orientation button changes its viewport without recreating the game document or reconnecting the room. Touch devices can use a rotated viewport even if the browser does not support orientation locking. Desktop portrait mode uses a centered vertical viewport. Room invitations point to the outer root URL.

Pinch zoom uses the stable document layout viewport for the iframe dimensions. Safari can report the magnified visual viewport through `innerWidth` / `innerHeight`; using those values collapsed the table and stacked its absolute seats. The frame is anchored to the document, and visual viewport events with unchanged layout dimensions no longer resize it. Browser magnification remains enabled. Run `node scripts/verify-zoom.cjs` for the 1.25×–3× zoom regression, including orientation changes during the same hand. The regression fails on the preceding `e8d9cf4` revision and passes with this fix. It uses Chromium page scaling plus Safari-style viewport reporting; it does not claim physical iPhone coverage.

The approved J/Q/K court characters appear as a larger header portrait outside the table. Normal phones use 112px, short phones 80–100px, tablets 144px and large desktops 160px, replacing the original 40px display. Phone branding and layout/menu controls stack beside the figure; larger screens keep those elements on one row. Clicking the portrait opens the three-character picker; choosing one returns directly to the game and remembers the preference on that browser. J uses the approved original design, Q the revised high updo and fan collar, and K the revised upright crown and authoritative expression. The picker includes an idle-motion checkbox, and the main menu can hide, restore or change the portrait. Characters stay silent. The old dealer panels, character chatter and narration remain retired; their hidden DOM preserves existing game bindings.

Portrait betting forms temporarily compact the header to retain room for choosing an amount. The figure returns to its larger size after confirming or cancelling. The existing marker-placement routine reruns after table layout changes and avoids both boards and the character bounds.

The dealer-position marker pairs a dark-green D disc with the visible label 庄家 on a light, high-contrast pill. It measures 66×30px, or 60×28px on short portrait phones, replacing the small 26px D-only disc. Its accessible label identifies the current dealer by player name. Placement uses the marker's actual rectangular bounds and checks nearby gaps around the owning player's plate, leaving hands, names, bets, blind markers and both boards clear.

`court-dealers.js` and `court-dealers.css` contain the new presentation component. The art is served as six optimized transparent WebP images in `public/assets/table-v2/`: three approved portraits and three generated blink frames. Only small feathered eye regions of each blink frame appear over the approved portrait, preventing regenerated clothing or silhouette edges from flickering. Breathing and blinking use CSS, stop with the motion preference, and respect the system's reduced-motion setting. Choosing a character makes no change to the poker engine or room state.

Private and community cards leave a dedicated position in the upper interior of the felt, independently of the header portrait's size, selection or visibility. Queued cards stay hidden until their individual deal delay expires. Deal paths account for the full rotated card bounds and avoid player identities and the header portrait before landing in the actual card slots. If an unusually tight layout has no clear corridor, the card fades in at its destination. Discard and chip-transfer animations retain their existing behavior.

Phone portrait has the primary three actions at the bottom. Landscape puts those actions beside the table. Six- and eight-player identities now form a ring outside the rail, including names, balances, action labels and current bets. Portrait uses compact avatar/name/balance columns; wide layouts retain horizontal plates. The presentation bridge measures the available arena and the player groups, then fits the felt inside that ring. Hands face the rail, while the community cards and pot keep their own clear central area. Landscape retains a horizontal oval. Short phones prioritize readable names and amounts over decorative avatars.

The helper strip above the actions stays visible in portrait, landscape and raise mode. It shows hand type, estimated equity and required equity for a call, using the existing game calculations. The player's balance stays on their seat plate, without a duplicate balance in the helper strip. The equity checkbox still controls its field; unavailable percentages show a dash instead of a stale value. Fields wrap between groups on narrow screens. Compact table proportions, middle card backs and dealer placement reserve room for the strip without covering community cards.

The pot now uses one small chip texture beside its numeric amount. Denomination piles, repeated chip layers and their alpha-profiling canvas are removed. The existing transfer-animation hook also uses one texture per transfer, preserving bet/raise sounds and movement. Phone layouts spread the three helper fields across the action area, use smaller opponent card backs and quiet frames for folded players, and omit the decorative table caption and redundant header subtitle. Board placement stays stable while the area below it opens up.

Interface typography uses the native Apple system stack (`-apple-system`, SF Pro and PingFang SC), with a system-font fallback on other platforms. Buttons, player names, amounts, menus and headings share that stack. Amounts use tabular digits for stable alignment. The printed ranks on the playing cards retain their dedicated card font; no Apple font files are downloaded or bundled.

Verification: `node scripts/verify-ui.cjs` requires Playwright and Chromium. The script uses the project's existing `?selftest` entry point; test setup is confined to this diagnostic URL. Results are in `artifacts/verification.json`. Both six- and eight-player layouts are checked at 320×568, 360×640, 390×740, 390×844, 768×1024, 1024×768, 844×390 and 1440×900: 16 combinations. The checks assert that player groups stay outside the rail and do not collide, and that hands and bets leave all five board slots, the street and the pot clear. A known royal flush verifies 100% equity, and a 40-chip call into a 240-chip pot verifies the rounded 14% requirement. Visibility while raising, the equity toggle and clearing folded-hand estimates are also checked. Physical Safari/iPad testing remains a device check for rollout.

`python scripts/export-preview.py` creates `artifacts/holdm-preview.html`, a self-contained solo preview with all fonts and images embedded. Room play uses the normal Node server. The portable preview was verified as an in-memory document without external HTTP requests and with its game document retained across orientation toggles.

`node scripts/verify-dealers.cjs` checks the new picker at eight phone, tablet and desktop viewports. It covers header and dialog bounds, all three characters, silent controls, persistence, hiding/restoring the portrait, optional motion, reduced motion, and preserving the live hand across selection and orientation changes. The existing 16-layout, action-audio and pinch-zoom checks also pass. Visual comparisons and results are recorded in `design-qa.md` and `artifacts/dealer-verification.json`.

`node scripts/verify-dealing.cjs` samples the real browser deal animations at the same 16 six/eight-seat viewport combinations. It verifies a shared table source, invisible queued cards, paths that avoid portraits and player plates, correct hand-slot landings, and unchanged hand/chip state. Flop, turn and river flights are checked separately in every combination. Results are in `artifacts/dealing-verification.json`, with a phone animation frame in `artifacts/dealing-phone.webp`. The origin assertions also reproduce the face-origin bug on the preceding `295696c` revision.

`node scripts/verify-dealer-marker.cjs` checks every dealer seat at the same 16 viewport/seat-count combinations, with preflop blind markers, a flop, and two boards: 336 positions. It verifies the complete visible label, the current player's accessible name, arena bounds and clearance from cards, player information and bets. It uses reduced motion to inspect settled geometry. Results and three phone/landscape captures are in `artifacts/dealer-marker-verification.json` and `artifacts/dealer-marker-*.webp`.
